## 1. Scope & Constraints

### In scope

- Extending `src/backends/opencl/type_mapping.py` with FP8 dtype → OpenCL type mappings.
- Including the generated FP8→FP32 conversion lookup tables in `kernels.cl.h` (generated by Phase 9A.1.5).
- Implementing `load_storage_fp8()` and `store_storage_fp8()` inline functions in `kernels.cl.h` with both FP32 and FP16 compute type variants.
- Extending the precision boundary macros to dispatch to FP8 functions when `STORAGE_TYPE_IS_FP8 == 1`, with appropriate widening to `COMPUTE_TYPE` (half or float).
- Adding build flag emission for `STORAGE_TYPE_IS_FP8`, `STORAGE_TYPE_IS_E4M3`, `STORAGE_TYPE_IS_E5M2`.
- Adding OpenCL-specific FP8 roundtrip tests.

### Out of scope

- Native FP8 extension support (`CL_FP8_NATIVE`) — no such extension exists; software emulation is the only path.
- SIMD FP8 operations — FP8 is processed element-by-element via lookup tables.
- CPU backend changes — deferred to Phase 9C.
- Vulkan backend changes — deferred to Phase 9D.
- Host-side scaling logic — deferred to Phase 9E.

### Key constraint: FP8 as `uchar`

OpenCL has no native FP8 type. FP8 storage buffers are declared as `__global const uchar*` or `__global uchar*`. All arithmetic is performed in `COMPUTE_TYPE` — either `half` (FP16) or `float` (FP32), depending on the precision configuration. Conversion functions handle the FP8↔COMPUTE_TYPE boundary.

**Future native FP8 support:** Some vendors may expose FP8 via OpenCL extensions (e.g., a hypothetical `cl_nv_fp8`). This implementation does not probe for such extensions — software emulation via lookup tables is the baseline. If native FP8 support becomes available, the conversion functions in `kernels.cl.h` can be conditionally compiled to use intrinsics while maintaining the same function signatures.

### Step 9B.3: Implement FP8 `load_storage` / `store_storage`

**Governing authority:** ADR-025 §4, §6.2  
**File:** `kernels/kernels.cl.h`

Add inline conversion functions supporting both FP32 and FP16 compute:

```c
#if STORAGE_TYPE_IS_FP8

// --- FP8 Load (storage → compute) ---
// Returns COMPUTE_TYPE (half, float, or double)
// Note: LUT stores float values. FP8→float is lossless (all 256 FP8 values
// are exactly representable in float). FP16 compute narrows; FP64 widens.
static inline COMPUTE_TYPE load_storage_fp8(__global const uchar *buf, size_t idx) {
#if STORAGE_TYPE_IS_E4M3
    float f32_val = fp8_e4m3_to_float_lut[buf[idx]];
#elif STORAGE_TYPE_IS_E5M2
    float f32_val = fp8_e5m2_to_float_lut[buf[idx]];
#endif

#if COMPUTE_TYPE_IS_HALF
    return (half)f32_val;    // Narrow to FP16 compute
#elif COMPUTE_TYPE_IS_DOUBLE
    return (double)f32_val;  // Widen to FP64 compute (lossless)
#else
    return f32_val;          // FP32 compute
#endif
}

// --- FP8 Store (compute → storage) ---
// Accepts COMPUTE_TYPE (half, float, or double), converts to FP8
static inline void store_storage_fp8(__global uchar *buf, size_t idx, COMPUTE_TYPE val) {
    // Narrow to float for bit manipulation (FP8 fits in float exactly)
    float fval = (float)val;
    
    // Handle sign
    uint sign = (fval < 0.0f) ? 1 : 0;
    fval = fabs(fval);
    
#if STORAGE_TYPE_IS_E4M3
    // E4M3: bias=7, max=448, min_subnormal=2^-9
    const float MAX_VAL = 448.0f;
    const float MIN_SUBNORMAL = 0.001953125f;  // 2^-9
    
    // Saturation
    if (fval >= MAX_VAL) {
        buf[idx] = sign ? 0xFE : 0x7E;  // Max magnitude (saturation, no inf)
        return;
    }
    if (fval < MIN_SUBNORMAL * 0.5f) {
        buf[idx] = sign ? 0x80 : 0x00;  // Zero
        return;
    }
    
    // Extract FP32 exponent and mantissa via bit cast
    uint fbits = as_uint(fval);
    int exp32 = ((fbits >> 23) & 0xFF) - 127;  // Unbiased exponent
    uint mant32 = fbits & 0x7FFFFF;            // 23-bit mantissa
    
    // Compute FP8 exponent
    int exp8 = exp32 + 7;  // E4M3 bias = 7
    
    // Handle subnormals
    if (exp8 <= 0) {
        int shift = 1 - exp8;
        mant32 = (mant32 | 0x800000) >> shift;
        exp8 = 0;
    } else if (exp8 >= 15) {
        buf[idx] = sign ? 0xFE : 0x7E;
        return;
    }
    
    // Round mantissa to 3 bits (round-to-nearest-even)
    uint mant8 = (mant32 + (1 << 19)) >> 20;
    if (mant8 >= 8) {
        mant8 = 0;
        exp8++;
        if (exp8 >= 15) {
            buf[idx] = sign ? 0xFE : 0x7E;
            return;
        }
    }
    
    buf[idx] = (sign << 7) | (exp8 << 3) | (mant8 & 0x7);
    
#elif STORAGE_TYPE_IS_E5M2
    // E5M2: bias=15, max=57344, min_subnormal=2^-16
    const float MAX_VAL = 57344.0f;
    const float MIN_SUBNORMAL = 0.0000152587890625f;  // 2^-16, exact
    
    // Saturation
    if (fval >= MAX_VAL) {
        buf[idx] = sign ? 0xFB : 0x7B;  // Max magnitude
        return;
    }
    if (fval < MIN_SUBNORMAL * 0.5f) {
        buf[idx] = sign ? 0x80 : 0x00;  // Zero
        return;
    }
    
    // Extract FP32 exponent and mantissa via bit cast
    uint fbits = as_uint(fval);
    int exp32 = ((fbits >> 23) & 0xFF) - 127;
    uint mant32 = fbits & 0x7FFFFF;
    
    // Compute FP8 exponent
    int exp8 = exp32 + 15;  // E5M2 bias = 15
    
    // Handle subnormals
    if (exp8 <= 0) {
        int shift = 1 - exp8;
        mant32 = (mant32 | 0x800000) >> shift;
        exp8 = 0;
    } else if (exp8 >= 31) {
        buf[idx] = sign ? 0xFB : 0x7B;
        return;
    }
    
    // Round mantissa to 2 bits
    uint mant8 = (mant32 + (1 << 20)) >> 21;
    if (mant8 >= 4) {
        mant8 = 0;
        exp8++;
        if (exp8 >= 31) {
            buf[idx] = sign ? 0xFB : 0x7B;
            return;
        }
    }
    
    buf[idx] = (sign << 7) | (exp8 << 2) | (mant8 & 0x3);
    
#endif
}

// --- Unified load_storage / store_storage macros ---
#define load_storage(buf, idx) load_storage_fp8((__global const uchar*)(buf), idx)
#define store_storage(buf, idx, val) store_storage_fp8((__global uchar*)(buf), idx, val)

#endif // STORAGE_TYPE_IS_FP8
```

**Note on FP64 precision:** When storing FP64 compute results to FP8, values are first narrowed to float (which may lose precision for values outside float's range), then quantized to FP8. This is acceptable because:
1. FP8's range (max 448 or 57344) is well within float's range (~3.4e38)
2. Values destined for FP8 storage should already be scaled to fit by the host
3. FP64 values > float max would already exceed FP8's range and saturate anyway
4. The narrowing step is exact for all values ≤ FP8 max (since FP8 ⊂ FP32 ⊂ FP64)

The key insight: FP8↔FP16 conversion routes through FP32 intermediate since all FP8 values are exactly representable in FP32.

## 4. Technical Notes

### FP8 conversion performance

The lookup table approach for FP8→FP32 is optimal (single memory access). FP32→FP8 conversion requires bit manipulation (~15-20 ALU operations per value). For bandwidth-bound workloads, the conversion overhead is amortized by the 4× reduction in memory bandwidth.

### Constant memory limits

OpenCL constant memory is typically 64KB per kernel. Each FP8 lookup table is 256×4=1KB. Two tables (E4M3, E5M2) require 2KB. This is well within limits.

### No native FP8 fast path

As of 2026, no OpenCL extension provides native FP8 types. The software emulation path is the only implementation. The `CL_FP8_NATIVE` codepath (ADR-025 §6.1) is a placeholder for potential future extensions.
